# Limited client pilot: implementation and launch status

Owner authorization covers a seven-day protected pilot using the existing Mumbai Supabase project; automatic backups are explicitly not required. No real records, credentials or source workbooks belong in this repository.

The owner identified the Vercel team as Hobby and subsequently instructed that actual commercial use must remain gated until an eligible plan and security acceptance are in place. Vercel's published fair-use rules limit Hobby to personal, non-commercial use. Do not upgrade or purchase a service, or interpret the earlier demonstration deployment as evidence of pilot readiness.

The Mumbai project was inspected through the owner's browser: PostgreSQL 17.11, zero public tables at inspection, and Data API disabled. The connected Supabase app is authenticated to another organization. The browser's read-only query succeeded. Recurring `pg_pgrst_no_exposed_schemas` errors match Supabase's documented behavior when Data API is disabled; do not enable it to silence these messages. No migrations or real-data imports have been performed.

The local branch includes a gated real-pilot Vercel entrypoint, restricted delivery attendance role, audit-safe account disabling and password reset APIs, Excel import validation, and activity, duty and follow-up Excel/PDF reports. Delivery financial and delivery-recording screens are intentionally unavailable in the real pilot until they have a secure tested backend. No individual staff account has been provisioned yet.

The reports provide a manual export of recorded visits (including discussion and order information), duty/break records and follow-ups. **These exports are not a database backup**: they do not reproduce accounts, sessions, audit history or the complete database. On a free database plan with no automatic backup, device or database failure can permanently lose pilot data. Preserve the two original workbooks and arrange regular private exports of all three reports, stored securely by an identified responsible person.

Remaining release prerequisites include resolving the hosting provider's commercial-use restriction, secure database and separate migration/runtime credentials, a privately provisioned first admin and staff accounts, a reviewed final import manifest, hosted PostgreSQL integration and end-to-end checks, and a usable private onboarding/recovery process. Do not place passwords in public source files, logs or chat. Verify the Vercel deployment contains the Node 22 function and only server-side database credentials; do not expose the browser-local demonstration transport or financial features. Keep automatic deployment disabled and do not replace the demo.

Local access rules: managers may manage sales and delivery accounts; only admins may create or change manager/admin accounts. Account changes revoke sessions. An account cannot change its own role or disable itself. To avoid stranding work, a role change is blocked while duty or a visit is open, or while an executive still has assigned shops or pending follow-ups. An enquiry cannot be transferred while an open visit or pending follow-up exists; finish that work first. These conservative rules need client review.

Recovery is currently a manager/admin setting a new password and communicating it privately; there is no self-service password change, expiring invitation, or automated reset email. Do not describe this as a self-service recovery system. Before onboarding, establish a private process for distributing unique strong passwords and review whether staff-controlled password changes are required. Do not assume a sign-in identifier is a verified email inbox.

The import is prepared for 524 customers and 424 enquiries, with eight unassigned enquiries and one authorized blank formula-error contact. Import requires real staff IDs, an approved batch manifest, a separate temporary import operator and reconciliation of the reviewed flags. Original spreadsheets remain the authoritative complete source; the mapping does not copy every historical source field. No client import or hosted integration has been run. The operator grants include narrowly scoped column updates required for row locks; the operator can directly alter those columns and must be privately controlled and revoked after use. See `operations/import-grants.sql`.

Use a separate, restricted Preview for hosted checks with fictional records only, with verified deployment protection and the application's own authentication. Vercel Standard Protection does not automatically protect every production domain; verify the actual selected protection scope. Configure the exact HTTPS origin, Node 22, Mumbai function region where supported, server-only TLS-verified transaction-pooler credentials, migration checksums and the restricted runtime role. The current exact-origin guard and real-pilot approval gate must remain enabled. The hosted PostgreSQL connection, account onboarding, exports and cross-device isolation must pass before real records or business use.
