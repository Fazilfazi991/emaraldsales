# Client usability acceptance — pending owner/client execution

Engineering checks do not tick this checklist. Record tester, device, date, difficulty and decision. Let a first-time user attempt tasks without coaching before offering the walkthrough.

## Executive

- [ ] Signs in and recognizes Today / Your working day.
- [ ] Starts duty and understands duty and visits are separate.
- [ ] Finds Al Noor quickly, recognizes an active filter and clears it.
- [ ] Reads earlier visits and checks in without instructions.
- [ ] Chooses an outcome, enters a short discussion and saves checkout.
- [ ] Notices confirmation and finds the completed visit.
- [ ] Adds one intended follow-up and recognizes due date/owner.
- [ ] Takes a break, returns and ends duty.
- [ ] Finds records after refresh and fresh login.
- [ ] Recovers with Retry save without duplication.

## Manager

- [ ] Understands current duty, date-bound visits and current pending work.
- [ ] Selects dates/executive without confusing pending/overdue scopes.
- [ ] Identifies pending follow-ups and opens customer history.
- [ ] Finds Reports and downloads; downloads Excel/PDF unaided.
- [ ] Understands selected dates/staff, generation time, totals and every break interval.
- [ ] Accepts Arabic/Malayalam/Latin spelling, shaping and reading order.
- [ ] Understands filters reset on fresh login while records persist.

## Devices and policy decisions

- [ ] Actual Android/iPhone keyboard, touch, location and downloads accepted.
- [ ] 390, 430, 768, 1024 and 1440px displays comfortable for intended staff.
- [ ] Terminology accepted: shop, New shops, Team, duty and outcomes.
- [ ] Check-in-date rows versus checkout-date completed totals accepted.
- [ ] No automatic end at midnight, return before end and sequential duty sessions accepted.
- [ ] Missed-event correction authority, shift/rest limits and lead conversion defined before adding those operations.
- [ ] Account recovery/offboarding, retention/privacy, backups and hosted operations assigned.
